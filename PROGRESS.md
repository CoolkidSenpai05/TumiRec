Added `serving_sim/memory_cache.py` with versioned user keys, detached snapshot values, LRU storage, TTL/refresh queue, future-snapshot rejection and out-of-order refresh protection; `memory_profile.py` exercises cache publication/reuse and records actual cached/uncached forward timings. Added `model/h2_baseline.py` and `train/h2_memory.py` for a co-trained memory side branch on the unchanged M3 causal control, bf16, clipping, warmup/cosine scheduling, exact epoch resume and validation-selected fixed-lag evaluation. Added `scripts/run_h2.py`, H2 YAML and protocol documentation. No unified backbone, S3 training or M5/M6 functionality implemented.
- **Tests:** Initial full suite: 73 passed in 15.80s. Final full suite: **77 passed in 54.10s**, CPU only and under two minutes, including all 55 earlier tests plus 22 M4 cases. Covers shapes/empty/no-memory behavior, strict lag/future/equal-time exclusion and zero excluded gradients, unsorted histories/window bounds, 1000-event input, action/time signals, session pooling, checkpointed bf16 backward, frozen content and masking, deterministic weighted lag sampling, cache miss/hit/stale/version/future/LRU behavior, actual measured profile samples and cache-score equivalence, disabled-memory baseline equivalence, exact training resume and all four H2 modes across two seeds/three lags with aggregation checks. Output JSON and positive measured timings were verified; the synthetic one-day lag retained older behavior history. No real-data or deployment-performance claims.
- **Assumptions / deviations from SPEC.md:** M4 experiments add a projected mean-memory residual to the M3 recent context; this is a scoped control rather than the future unified architecture. All H2 variants keep identical online recent history: none disables the memory branch, recent_only compresses only the recent-size window at the memory cutoff, behavior_memory uses up to 1000 events, and content_pool adds the masked mean of frozen content before final normalization. `no_memory` is an encoder alias of none. Time buckets use the snapshot cutoff rather than request time so cache reuse is well-defined. Session gaps split only when strictly greater than the threshold. Cache stores `(K,D)` tokens, not future backbone projected attention K/V; refresh is explicitly caller-driven without threads. TTL uses event-time cutoff difference. A separate H2 CLI preserves the completed M3 runner instead of modifying earlier code. Fresh validation selects one checkpoint shared across all lag evaluations. Optional timing excludes cache lookup/refresh, loading and transfers; small smoke sample counts validate instrumentation only, and general latency benchmarking remains M6.
- **Changes to earlier milestones (if any) and why:** No M1–M3 implementation or tests changed. Reused their splits, statistics, tokenization, causal baseline, seed/scheduler helpers and metrics. Updated only shared README/package/experiment documentation and progress statuses; H1 runner remains unchanged.
- **Possible leakage / unfair-baseline / protocol concerns:** Both dataset and encoder enforce strictly earlier event cutoffs; validation/test histories remain TRAIN-only and current recent history remains fresh while memory lags. Static TRAIN statistics/SID fitting, per-user splits and catalog metadata snapshot caveats from M3 remain. Cache publishers must honor cutoff provenance and change version for changed weights/catalog/config; cached detached tensors are never used during training. Controls have equal budgets but different active parameters and have not been independently tuned. Synthetic content is random test data, not semantic embeddings. Per-run timings are measured diagnostics, not evidence that H2 improves quality or latency.

### M2 — Offline tokenizer, S1 training, diagnostics and tests (2026-10-21)

Added `train/stage1_tokenizer.py` with bf16 autocast, deterministic seeds, gradient clipping, warmup/cosine LR, activation checkpointing, epoch-boundary checkpoint/resume, CSV logs, parquet SID export and JSON diagnostics. Added S1/content YAML configs, manual opt-in encoder preparation instructions, and README usage/design decisions. No M3 or later functionality implemented.
- **Tests:** First full suite passed 34 tests in 15.48s. Final full suite passed **35 tests in 8.21s**, including all 20 M1 tests and 15 M2 cases. Tests cover frozen/offline cache reuse and rejection, positive-pair boundaries, hand-computed InfoNCE, adapter learning, RQ shapes/usage/reconstruction improvement (random and k-means init), dead-code resets, stable SID collision suffixes, catalog diagnostics, exact resume during either training phase, config ablations, and invariance of fitted weights to changed cold-item features with/without the adapter. A separate synthetic S1 CLI run succeeded and produced `/tmp/tumirec-m2-smoke/{checkpoint.pt,training.csv,sids.parquet,diagnostics.json}` for 24 catalog items and 20 train-observed items. These are synthetic plumbing outputs, not recommendation benchmark results.
- **Assumptions / deviations from SPEC.md:** Chose gradient-trained codebooks with residual k-means initialization (the specified alternative to EMA); EMA is not implemented. RQ-VAE is a deterministic vector-quantized autoencoder without a Gaussian/KL term. Deadness counts training forwards; reset rows have Adam momentum cleared. Collision suffix is a catalog-local ordinal with vocabulary equal to the largest collision group, unconstrained by codebook size. TRAIN-only fitting excludes cold item features, while SID export transforms the full catalog. Resume is at epoch boundaries with identical inputs/config. Synthetic CLI uses explicitly seeded random features rather than pretending to provide text embeddings. Actual sentence-transformer and OmegaConf packages are absent in this environment; no packages/weights were downloaded or installed. Real encoder execution and GPU behavior were not tested. Cache identity assumes immutable model names/paths; concurrent cache writes are unsupported.
- **Changes to earlier milestones (if any) and why:** No M1 implementation or tests changed. Extended packaging with the optional sentence-transformers `text` dependency and updated shared README/status documentation for M2. No commit created because the directory remains outside a Git repository.
- **Possible leakage / unfair-baseline / protocol concerns:** Positive pairs and tokenizer fitting depend on callers supplying TRAIN-only interactions. Cold/unobserved item features do not affect fitted weights; catalog metadata must still use the evaluation-appropriate snapshot. SIDs are catalog-local and collision suffixes may change when rebuilding a changed catalog, so persist the mapping per experiment. In-batch negatives can include other behavioral positives despite duplicate/self masking. Full-catalog reconstruction includes cold items and is separately labeled from train reconstruction. No real recommendation metrics or baseline comparisons claimed.
